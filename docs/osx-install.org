#+title: Installing Emacs on OSX

Steps to bring this configuration up on a fresh OSX machine. See also
[[file:index.org][the docs index]] and [[file:config-reorg.org][the configuration reorganization proposal]].

* Install GUI Emacs

Two routes; =emacs-plus= is preferred because it ships native-comp and
tree-sitter, matching the Linux build (=eln-cache=, libgccjit).

** emacs-plus (recommended)

#+begin_src sh
brew tap d12frosted/emacs-plus
brew install emacs-plus@31 --with-native-comp
ln -s /opt/homebrew/opt/emacs-plus@31/Emacs.app /Applications/Emacs.app
#+end_src

Useful extra flags: =--with-imagemagick=, =--with-poll=, an icon such as
=--with-modern-doom3-icon=. Version taps =@31= / =@30= / =@29= — pick one;
=@31= matches the Linux 31.1 build.

** Homebrew cask (simpler, upstream build)

#+begin_src sh
brew install --cask emacs
#+end_src

* Build tools for native modules

vterm compiles a C module through CMake. Install Homebrew's libvterm so
the build can link it directly, avoiding a separate source download and
GNU libtool build.

#+begin_src sh
brew install cmake libvterm
#+end_src

* PATH: let Emacs see brew tools

GUI Emacs on OSX does not inherit the shell =PATH=, so brew binaries in
=/opt/homebrew/bin= are invisible to compile subprocesses even after
installing them. The config handles this with =exec-path-from-shell=,
initialized in =init.el= before package provisioning and vterm loading
(=:ensure t=, so a fresh machine installs it automatically). On macOS,
the config also passes Homebrew's libvterm prefix to CMake when installed,
supporting both Apple silicon and Intel prefixes.

Nothing to configure by hand — just restart Emacs after the brew installs so
=exec-path-from-shell-initialize= picks up the updated =PATH=.

* Key remapping

OSX-specific settings live in =src/mijn-darwin.el= (guarded by
=(eq system-type 'darwin)=). Command and Option provide Meta by default.

If the selected profile in =~/.config/karabiner/karabiner.json= maps Caps
Lock to left Command, Emacs treats left Command events as Control. In this
profile, physical left Command maps to Option and therefore still provides
Meta; right Command also provides Meta. Machines without that Caps Lock
mapping keep the default modifier behavior. Restart Emacs after changing
Karabiner profiles. Karabiner's system-wide mappings stay unchanged.

* Verify

1. Restart Emacs.
2. =M-x vterm= — the module compiles and opens a working shell.
3. Paths: =M-:= =(executable-find "cmake")= should return a path.
4. Module support: =M-:= =module-file-suffix= must be non-nil. An Emacs
   build without dynamic module support needs to be replaced.

For a failed previous build, run =M-x vterm-module-compile= after restarting.
The build output should say =System libvterm detected=. A downloaded
libvterm build requires =brew install libtool= (=glibtool= on macOS).

* Apple silicon vs Intel

Brew prefix differs: =/opt/homebrew= on Apple silicon, =/usr/local= on Intel.
Adjust the =Emacs.app= symlink path accordingly.
